# stm32-learning

STM32 学习仓库：外设 demo + 踩坑记录。
**目标**：2027 年 3–5 月拿到嵌入式 / 固件岗 offer。计划 32 周（2026-09-28 → 2027-05-09），每周约 15.5 小时。

---

## 每天上传什么

一句话：**今天写了什么代码、遇到什么坑，就传什么。**

| 该上传 | 不该上传 |
|---|---|
| 源码（`.c` `.h`，含工程文件） | 编译产物（`.o` `.hex` `Objects/` `Debug/`）—— 已写进 `.gitignore` 自动忽略 |
| 每个实验文件夹里的 README（现象 + 踩坑） | 盗版电子书、付费视频（版权风险，对你也是减分项） |
| `docs/踩坑记录.md` 的更新 | 超过 100MB 的大文件（GitHub 会直接拒绝） |
| 原理图 PDF、PCB 图、波形截图 | 演示视频（传到 B 站，README 里放链接） |
| 上位机 Python 脚本 | 芯片 datasheet（体积大，放链接即可） |

**最小可执行标准**：哪怕今天只点亮了一颗 LED，也传——一个能跑的小工程 + 三行 README。绿格算的是"今天有没有提交"，不是代码量。

## 怎么上传

**方法 A（推荐，30 秒）**：双击仓库外面的 `每天提交.bat`，输入一句话说明，回车，自动完成。

**方法 B（命令行）**：

```bash
cd D:\Code\stm32-learning
git add .
git commit -m "feat(gpio): LED 流水灯，搞懂推挽与开漏区别"
git push
```

**方法 C（没网时）**：照常双击 `每天提交.bat`，提交会成功、推送会失败，脚本会告诉你"已安全存在本地"。回到有网的地方双击 `补推送.bat`，一次性全推上去。

## commit 怎么写

格式：`类型(模块): 一句话`

- `feat` 新功能 · `fix` 修 bug · `refactor` 重构 · `docs` 文档 · `perf` 优化
- 例：`feat(adc): DMA 双缓冲采样 1kHz`、`fix(usart): 空闲中断丢最后一字节`
- 一个外设一个 commit，别攒成一整天一个"更新代码"
